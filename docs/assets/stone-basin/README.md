# 白天与夜晚水体迁移记录

用户于 2026-11-01 采用 D3R、T3R、N3R 宽瀑布修订稿，并授权保存、提交及迁移白天和夜晚。设计归档提交为 `0bb745d`。黄昏稿保留在设计归档，本次运行版本包含白天、夜晚。

## 美术输入和过程

1. 白天以已确认 D3R 为编辑对象，保持构图、宽瀑布、石桥、石阶和岸线，移除预画角色及水面特效。
2. 夜晚以清理后的白天底图为几何对象，以 N3R 为光色参考，保留暖灯和珊瑚局部发光，移除湖面预画光带。
3. 用 Python 生成技术数据遮罩，没有用 Python 重绘美术。引擎按共享数据绘制两版水体，角色复用原实验的 ImageGen 四方向图集。

内置 ImageGen 的完整输入保存在 [白天提示词](day-plate-prompt.txt) 和 [夜晚提示词](night-plate-prompt.txt)。[资产清单](asset-manifest.json) 记录输入与输出哈希及原始生成文件名。内置工具未提供模型版本或随机种子，记录用于溯源，不能保证再次生成完全相同的像素。

“归约细节”落实为减少水面碎亮点、复杂白线和焦散网，用较大的连贯像素色块保留深浅和海床结构。没有对画面做整体模糊处理。

## 运行时结构

| 内容 | 实现和边界 |
| --- | --- |
| 深浅与折射 | 共享 RGBA 技术图，折射按逻辑像素取整，拒绝岸外采样 |
| 水底焦散 | 缓慢移动的低对比函数纹理，随深度减弱 |
| 岸线泡沫 | 沿水域距离场移动，干地不参与着色 |
| 交互涟漪 | 点击与水中移动生成最多 16 个衰减事件 |
| 角色浸没 | 局部高度与曲面水线，水下变色、变淡并扰动，深水保留头部 |
| 角色倒影 | 翻转角色副本，受水域约束，随浸没变淡 |
| 瀑布与汇流 | 原画连续水幕双相滚动采样、局部泡沫扰动、落点向外传播的波纹 |
| 夜间光带 | 动态破碎月光和暖灯光带，桥身原画颜色的二维投影 |
| 遮挡与导航 | 前景颜色取自原画，依据脚点高度遮挡；2 像素 AStar 网格绕行突出礁石 |

宽瀑布源图和即时落水白沫仍属于底图。开关控制流动及汇流动画，关闭后是静态瀑布。海床颜色和夜间珊瑚发光属于生成图，不是物理光照求解。所有水下石块尚未逐个建立体积与碰撞；当前测试范围是已校准的河岸、石阶、水路和主要礁石。

## 验证方法

验收使用 Godot 4.7.2、OpenGL Compatibility、NVIDIA RTX 4070 SUPER 的真实 X11 窗口。headless 只用于导入检查，没有用空渲染器代替画面验证。性能采样先预热 2 秒，再记录约 3 秒实际绘制帧数；CPU 数据来自 Godot 的进程时间监视器，记录中位数、P95 和最大值，普通窗口验收未单独测量 GPU 着色耗时。固定帧率策略为 60 FPS。

`audit_stone_basin.gd` 保存两版截图，派发真实按键事件和场景点击事件，模拟完整往返及礁石绕行。`check_stone_basin_render.py` 对 GPU 截图做逐像素对照，检查岸外修改、黑块、时间冻结、瀑布越界、各层实际变化、前后遮挡和像素网格。边界像素检查证明效果遵守当前遮罩，不能替代对整幅画面所有物件的语义审核。

完整数据在 `../../../evidence/stone-basin/runtime-report.json` 与 `render-checks.json`。旧洞窟回归检查单独保存在 `../../../evidence/legacy-regression/`，旧实验的原始证据没有覆盖。

## 实际修正

实机验证发现环境反光的幂运算在负底数下产生无效颜色，已改为先取绝对值。前景棕榈宽轮廓曾覆盖叶间水面，已将水色间隙从遮挡数据中排除。原图模式进入深度图时曾没有恢复角色显示，已修正并加入状态检查。自动漫游首次检查受到测试按键释放时序干扰，已等待输入帧完成后再模拟，随后验证完整返回起点。
